# 02 Improve

## Task

Обнови ADR-файл на основе JSON после `01_review`.

Этот шаг должен вносить осмысленные правки прямо в файл ADR, а не только комментировать, что стоило бы поменять.

## Input

- путь к файлу ADR;
- JSON после `01_review`.

## Focus

- применить все правки, которые можно сделать без выдумывания фактов;
- сохранить исходный смысл ADR, если ревью не требует его изменить;
- улучшить ясность, полноту, структуру и формулировки;
- отдельно зафиксировать, что осталось заблокировано вопросами к человеку.

## Rules

- не придумывай новые факты, решения, метрики, ссылки, даты или зависимости;
- не меняй `decision_status`, если это прямо не следует из входа;
- соблюдай статусную семантику:
  - для `proposed` не превращай предложение в уже принятое решение;
  - для `accepted` не размывай уже принятое решение до уровня гипотезы;
- если `decision_status` = `accepted`, не оставляй в ADR placeholders, TODO или явно незавершенные формулировки;
- если ADR остается в `proposed`, допустимы только минимальные явно помеченные незакрытые места, которые нельзя честно снять без ответа человека;
- если issue можно исправить редакторски, исправь;
- если issue требует отсутствующих данных, не фантазируй: оставь это в `unresolved_questions`;
- сохраняй существующий текст, если он корректен;
- меняй только проблемные участки;
- не делай stylistic rewrites без причины;
- сохраняй markdown-структуру ADR и обязательные секции;
- если входные данные конфликтуют, следуй подтвержденным фактам из ADR и связанных документов;
- если конфликт нельзя надежно разрешить, явно оставляй его в `unresolved_questions`, а не выбирай произвольную версию;
- меняй файл ADR по месту;
- не добавляй пояснительный текст вне JSON.

## Output

Верни только JSON с полями:
- `applied_changes`
- `unresolved_questions`
- `status`

Используй такой контракт:

```json
{
  "applied_changes": [
    {
      "issue_id": "ISSUE-01",
      "section": "Название секции ADR или frontmatter",
      "change_summary": "Что именно было изменено"
    }
  ],
  "unresolved_questions": [
    {
      "question_id": "QUESTION-01",
      "section": "Название секции ADR или frontmatter",
      "question": "Что нужно уточнить у человека",
      "blocked_change": "Какое улучшение нельзя надежно внести без ответа"
    }
  ],
  "status": "fully_updated | partially_updated | needs_human_input"
}
```

Правила для `status`:

- `fully_updated` — все замечания, которые можно было исправить без человека, исправлены; блокирующих вопросов не осталось;
- `partially_updated` — часть замечаний исправлена, но остались вопросы или блокеры;
- `needs_human_input` — meaningful-правки почти полностью упираются в отсутствующие ответы.
