## Product Context

Chancer — AI-помощник для прогнозирования ставок на матчи по CS2. Целевой пользователь — частный беттер, делающий ставки в удовольствие.

Основная задача системы: снизить ручную аналитическую нагрузку при принятии решения о ставке. Сейчас беттер вынужден самостоятельно собирать данные о форме команд, составах, head-to-head статистике и карточном пуле из разных источников (HLTV, Liquipedia, стримы), а затем вручную сопоставлять их с коэффициентами букмекера. Это занимает много времени и не позволяет систематически выявлять неэффективности рынка.

Ключевая гипотеза: на основе агрегированных данных о матчах и командах можно построить модель, которая достаточно точно оценивает реальные вероятности исходов — и тем самым находить ситуации, где коэффициент букмекера занижен относительно реальных шансов. Модель совершенствуется итерационно: прогнозы верифицируются по фактическим результатам, веса корректируются на основе ошибок.

Границы продукта на старте: данные поступают через PandaScore API (CS2), авторизация пользователей вне scope, интерфейс — чат на естественном языке.

## Core Workflows

- `WF-01` **Сбор данных** — загрузка и хранение матчей, команд, составов и статистики игроков через PandaScore API.
- `WF-02` **Аналитика** — расчёт формы команды, H2H-сравнение, анализ карточного пула и силы оппонентов.
- `WF-03` **Прогнозирование** — генерация прогноза на конкретный матч с оценкой вероятности победы и индикатором надёжности.
- `WF-04` **Чат-интерфейс** — ответы на свободные запросы пользователя на естественном языке; лента предстоящих матчей с быстрым прогнозом.
- `WF-05` **Обратная связь** — фиксация фактических результатов, отслеживание точности прогнозов (accuracy, ROI), корректировка модели.

## Constraints

- `PCON-01` Авторизация пользователей вне текущего scope.
- `PCON-02` PandaScore (бесплатный план) — основной источник данных; лимит 1 000 запросов в час. Архитектура сбора данных должна укладываться в этот лимит.
- `PCON-03` HLTV-скраппинг на паузе из-за анти-бот защиты; подключается как второй источник позже.
- `PCON-04` Новые Ruby-гемы добавляются только по явному согласованию.
- `PCON-05` Существующие миграции БД не изменяются и не удаляются.
